# EcoFlow Монітор

Веб-додаток тільки для **перегляду**: стан станцій EcoFlow, лічильник енергії по днях, порівняння
з попередніми періодами та журнал відключень світла. Нічого не змінює на станціях: код ходить
у API лише методами GET і підписується на MQTT-топіки `quota`/`status`.

## Швидкий старт

Потрібен Node.js 20+.

```bash
# 1. Демо без ключів (симульовані станції, 30 днів історії, блекаути)
cd server && npm install && npm run demo      # http://127.0.0.1:5000 (після збірки фронтенду)
cd ../web && npm install && npm run build     # збирає web/dist, який віддає сервер

# 2. Реальні станції
cd server
cp .env.example .env     # вписати ECOFLOW_ACCESS_KEY / ECOFLOW_SECRET_KEY
npm start
```

Ключі: <https://developer-eu.ecoflow.com> (для європейського акаунта; хост `api-e.ecoflow.com`).

Розробка фронтенду: `cd web && npm run dev` (проксі `/api` → бекенд; інший порт: `API_PORT=5055 npm run dev`).
Тести: `cd server && npm test`.

## Демо на GitHub Pages

`.github/workflows/pages.yml` при пуші в `main` (або вручну через *Run workflow*) збирає статичне демо:
запускає сервер у demo-режимі, знімає відповіді API в JSON (`web/scripts/snapshot.mjs`) і збирає фронтенд
з `VITE_STATIC=1`, щоб він читав ці файли замість бекенду. Дані зафіксовані на момент збірки, живого оновлення немає.

Одноразове налаштування: **Settings → Pages → Source: GitHub Actions**.

## Як це працює

- `server/src/ingest.js`: MQTT-підключення до брокера EcoFlow (облікові дані з `/iot-open/sign/certification`),
  REST-опитування `quota/all` як запасний варіант. Раз на 10 с пише знімок у SQLite.
- Енергія рахується інтегруванням потужності (Вт × час) в погодинні кошики `energy_hourly`.
  Дірки в даних (станція мовчала, сервер був вимкнений) не інтегруються, а відображаються як
  «покриття» дня: реальні значення в таких днях вищі за показані.
- Блекаут = напруга на AC-вході < 90 В; якщо напруги немає в даних, то евристика
  «вхід з мережі ≈ 0 при навантаженні > 5 Вт». Подія зараховується, коли стан тримається 30 с.
- Сирі знімки зберігаються 14 днів (`RETENTION_DAYS`), погодинні агрегати й блекаути, без обмеження.
- Порівняння тижнів/місяців іде по повних днях (сьогодні, неповний день, показується окремо).
- Часовий пояс днів: `Europe/Kyiv` (`TZ_NAME`).

## ⚠ Що треба перевірити на реальних станціях

Код **не тестувався на живих Delta 3 / River 2** (немає ключів). Відомі ризики:

1. **Назви ключів і одиниці.** `server/src/metrics.js` містить списки кандидатів для кожної метрики
   (заряд, вхід, вихід, мережа, сонце, напруга). Відкрий вкладку **«Дебаг»**: там видно всі сирі ключі,
   що прийшли, і що з них розпізналось. Звір з застосунком EcoFlow і поправ мапінг (особливо множники:
   наприклад `mppt.inWatts` у деяких моделей у десятих частках ват).
2. **Delta 3 (серія D361):** офіційний REST `quota/all` блокується (код 1006), а MQTT Developer API
   може мовчати, поки станція «спить» або не відкрито застосунок. Якщо в «Дебагу» порожньо, треба
   друге джерело даних: неофіційний вхід через email+пароль (MQTT застосунку, формат може бути protobuf).
   Це наступний крок, його ще не зроблено.
3. **Ключі Developer API дають повний доступ** (режиму «лише читання» немає). Тримай `.env` приватним.
4. Сервер **без авторизації**: за замовчуванням слухає тільки `127.0.0.1`. Якщо виставляєш назовні,
   став перед ним reverse proxy з паролем.

## Структура

```
server/src/  config · ecoflow (підпис, REST) · metrics (мапінг ключів) · ingest (MQTT, знімки, енергія)
             blackout · energy · stats (day/week/month) · db (SQLite) · mock (демо) · index (Express API + SSE)
web/src/     App.jsx (Зараз · Статистика · Блекаути · Дебаг) · api.js · format.js · styles.css
```

## Гілки

- `main` — стабільна гілка, лише релізи.
- `development` — основна гілка розробки: усі фічі вливаються сюди через PR, а на реліз `development` мержиться в `main`.
